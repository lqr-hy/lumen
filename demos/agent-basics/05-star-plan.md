# STAR 案例 Demo 实施计划

## 目标

把面试准备文档中的 5 个真实案例，转换为可运行的情景模拟，练习项目经理在 Agent 项目中的判断、推进和复盘能力。

## 案例计划

| 编号 | 面试案例 | Demo 模拟内容 | 对应 Agent 能力 |
| --- | --- | --- | --- |
| 1 | 需求范围冲突 | 页面整图 vs 可编辑组件的取舍 | 交付边界、Scene Graph、分层设计 |
| 2 | Provider 失败 | 生图超时后从 Checkpoint 继续 | Step、Checkpoint、恢复、错误码 |
| 3 | 跨团队延期 | 真实组件 Bundle 延期时用 Fixture 保主链 | 依赖拆分、接口契约、里程碑 |
| 4 | 质量问题 | Tool 假成功但 Canvas ACK 不通过 | 后置条件、质量门禁、局部 Repair |
| 5 | 错误判断 | 咨询请求误判成执行请求后的纠偏 | Intent Router、回归测试、复盘 |

## 运行步骤

```bash
node demos/agent-basics/04-star-cases.mjs
```

## 每个案例的复习方式

1. 先只看 `S` 和 `T`，尝试用自己的话复述问题和目标。
2. 再看代码，指出哪些逻辑是项目经理决策，哪些是系统机制。
3. 运行 Demo，观察日志中的失败、跳过、ACK 和恢复。
4. 合上代码，用 2—3 分钟按 STAR 讲一遍。
5. 追加一个数字：真实项目中的耗时、成功率、返工率或缺陷数；没有数字时说明数据缺失。

## 代码和真实项目的对应关系

- `checkpoints` 对应领域 Session/Artifact Repository 中的 Step 检查点。
- `Canvas ACK` 对应 Renderer 写入 DesignDocument 后返回的后置条件确认。
- `Fixture` 只用于验证非模型链路，必须标记为 `mock-only`，不能当作真实 Runtime 能力。
- `regression` 对应 Intent Router 和 Agent Runtime 的离线回归用例。
- `outputHash` 用于判断输入或依赖未变化时是否可以复用结果。

## 面试回答模板

```text
S：当时的业务/项目背景是什么？冲突或风险是什么？
T：我需要对什么结果负责？验收标准是什么？
A：我做了哪些拆解、取舍、协调和机制设计？
R：结果是什么？哪些是已验证结果，哪些数据需要补充？
复盘：如果重来一次，我会提前增加什么指标、测试或风险预案？
```

## 重要边界

这些 Demo 是基于仓库现有架构的可运行模拟，不代表真实线上用户量、成功率或团队协作数据。面试中应把“代码演示了机制”和“项目产生了业务结果”分开描述。
