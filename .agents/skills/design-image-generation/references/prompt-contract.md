# 生图 Prompt 契约

## 固定字段

- 原始任务：完整保留用户要求。
- 输出模式：`ui-page`、`page-background`、`isolated-asset`、`image-edit`、`marketing-visual` 或 `general-image`。
- 目标：素材名称、用途、宽高、透明度。
- 参考图：名称、序号和唯一职责。
- 不变量：不能改变的主体、结构、文案、颜色或未选区域。
- 禁止项：整页误生成、多个素材拼图、假透明、展示板、无关文案和解释文字。

## 参考图优先级

1. `edit-base`：编辑底图，决定必须保留的像素主体与构图。
2. `prototype`：结构原型，决定布局、模块顺序和已有文字。
3. `kv`：视觉主题，决定主色、材质、字体气质和装饰语言。
4. `visual`：普通视觉参考，只影响明确指定的视觉维度。

同一图片不能因为“看起来像”而越权承担其他职责。

## UI 设计稿

生成前先列出页面必须出现的区域。输出应像可评审的真实产品界面，而不是抽象插画、单张背景或只有色块的概念图。移动端默认按 375px 逻辑宽度组织；高度根据内容自然延展。

## 独立素材

每个任务只生成一个文件和一个主体。图片 Prop 承载完整按钮时，默认由模型直接生成带 Contract 准确文案的完整图片，最终只交付一个图片节点；只有明确使用 `embedded-exact` 时才由 Runtime 合成。只有 Contract 声明独立 Text Prop 时才保留 Canvas 文字节点。透明素材不绘制背景、设备框、页面上下文或其他组件。

`gpt-image-2` 的透明叶子素材允许使用纯 `#00ff00` 色键背景，由 Runtime 本地转换为 Alpha。色键背景必须完全均匀，不得包含阴影、渐变、纹理、反射或光照变化，主体不得使用色键颜色。

## 编辑

Prompt 必须包含：

- 仅修改的对象或区域。
- 保持不变的主体、身份、构图、文字和尺寸。
- 禁止重新设计整张图片。

## 质量检查

- 图片可解码且比例匹配目标。
- 关键文字可辨识，没有擅自改写。
- Prototype 与 KV 职责没有混淆。
- 独立素材没有拼图或页面截图。
- 透明 PNG 具有足够的真实透明像素，且没有棋盘格或大面积不透明底色。
