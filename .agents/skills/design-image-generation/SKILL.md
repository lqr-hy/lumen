# 通用设计生图

## 目标

把自然语言、画布目标和参考图编译为可执行的图片任务。最终必须生成图片并交付画布，不能只回复方案、HTML 或代码。

## 执行顺序

1. 判断任务是完整设计稿、页面背景、独立素材、图片编辑还是普通视觉图。
2. 明确每张参考图的唯一职责：Prototype 管结构和原文案，KV 管主题，Visual 管局部视觉，Edit Base 是必须保留主体的编辑底图。
3. 保留用户原始要求和准确文案，不擅自增加业务模块、品牌、角色或装饰。
4. 按目标尺寸和用途编译 Prompt，再调用 Studio 设计工作流；不要直接调用外部 CLI。
5. 检查尺寸、构图、文字、参考图一致性和真实透明度。失败时只针对问题重试一次。

## 输出模式

- **完整 UI 设计稿**：先满足基本信息架构和组件布局，再应用视觉主题；必须保留可识别的导航、标题、表单、按钮、列表或业务内容。
- **页面背景**：只生成底色、纹理和轻量装饰，不烘焙文字、按钮、卡片和业务组件。
- **独立素材**：每个任务只包含一个对象，不制作整页、展示板、对比图或多个素材拼图；边界贴合主体。
- **图片编辑**：明确“只改什么”和“什么必须保持不变”，优先保持主体身份、构图、文字和未选区域。
- **业务组件完整设计**：真实 Runtime DOM/PNG 是结构与原文案的最高优先级 Prototype，thumbnail 仅为次级参考，KV/Visual 只负责主题。默认交付一张无 UI 的氛围底图、声明式 Props 图片 Slot，以及可编辑 Runtime Text/Button/Surface/Image 节点；禁止用整张组件截图替代可编辑结构。
- **KV/海报**：建立明确视觉层级；需要图片内文字时逐字保留并说明位置。

## 模型策略

- `gpt-image-2`：优先用于准确文字、UI 布局、海报排版和位置约束。准确文案必须逐字引用。
- `nano-banana-pro`：优先发挥多参考图、主体一致性和编辑保持能力。必须逐张说明参考图职责和不可改变项。
- 用户已选择模型时不得擅自切换；Skill 只调整 Prompt 策略。

## 透明素材

透明任务必须返回带真实 Alpha 通道的 PNG。主体外像素为 `alpha=0`；禁止灰白棋盘格、白底、灰底、纯色底、画框、投影展示板和只在四角添加少量透明像素。

当当前 `gpt-image-2` 服务不能稳定兑现原生 Alpha 时，Runtime 使用纯 `#00ff00` 色键背景生成，并在 Raster Worker 中执行边缘采样、软遮罩、去绿边和 Alpha 校验。只有边缘色键覆盖率达到门槛才允许去色；否则按透明素材失败处理，禁止把绿色底图交付画布。

图片 Prop 承载完整按钮、标签等素材时默认使用 `model-exact`：模型直接生成包含 Contract 准确文案的完整图片，Canvas 不额外创建同文案 Text。只有 Provider 无法稳定生成文字且调用方明确要求确定性合成时，才使用 `embedded-exact` 生成无文字底图并由 Runtime 合成。

批量重生成同一组件的多个图片 Slot 时，每个 Slot 仍独立生成且不得复用含文字图片，但必须共享同一视觉一致性契约：轮廓语言、圆角比例、边框、渐变方向、材质、高光、阴影、字体风格、字号比例和内边距保持一致，只允许目标尺寸与准确文案不同。透明属性默认继承 Component Contract；用户没有再次说“透明”不代表改为不透明。Provider 不支持透明图片编辑时，保留 VisualTheme 后切换到透明生成，禁止输出白色展示底板。

详细契约见 [references/prompt-contract.md](references/prompt-contract.md)。Runtime 使用 `design-image-generation.compile-brief` 进行确定性编译。
